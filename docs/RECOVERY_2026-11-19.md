## 根因分析：bash 工具的 `rm -rf` 防护存在缺口

`tools/builtin/bash.go` 的 `checkHighRisk` → `dangerousRmTarget` → `isDangerousPath`
只拦截**宽泛目标**（`.` `..` `/` `~` `$HOME` `*` `.*` 及含通配的家目录路径），
**不拦截"家目录 / 工作区下的具体子路径"**。

实测（`checkHighRisk` 返回值，空串 = 放行）：

```
rm -rf /Users/admin/workspace/go-code                       => ""   ← 放行
rm -rf ~/workspace/go-code                                  => ""   ← 放行
rm -rf $HOME/workspace/go-code                              => ""   ← 放行
rm -rf /Users/admin/cybertron-gogroup                       => ""   ← 放行
find /Users/admin -maxdepth 2 -name go-code -exec rm -rf {} + => ""  ← 放行
rm -rf /Users/admin/workspace/go-code/.go-code/worktrees/*  => ""   ← 放行
```

现场删除模式与上述放行集合**完全吻合**：删的是具体路径（仓库根、worktree 目录、
`cybertron-gogroup` 整树），而非 `~` 或 `*`。

另外两条**未被拦截**的旁路：
- `find ... -delete` / `find ... -exec rm -rf {} +` —— `dangerousRmTarget` 按 token 流解析，
  `find` 不在命令位时状态作废，其 `-exec rm -rf {} +` 段落因 `{}` 不是命令位而不被判为 rm 调用
- 任何**非 bash 工具**发起的删除（如直接 `os/exec`、其它 agent、脚本）
