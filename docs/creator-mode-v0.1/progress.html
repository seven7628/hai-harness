      评审规则

      • 一提交一评审：每轮 commit 后由独立评审方（只读）评，结论三档：PASS / CHANGES / BLOCKED。
      • PASS 才进下一轮；CHANGES 在同一轮修复后重新评审，最多 3 次，第 4 次转 BLOCKED 并写裁决。
      • 评审输入：commit diff + 本轮验收命令输出 + 00-conventions.md §4 对应类别的 DoD。
      • 评审只读：不改代码、不提「顺便」，只给「必须改 / 建议 / 通过」三类结论。

          每轮四步

          角色  主会话 = 调度 / 验收 / 合并 / 清理 worktree / 更新看板
       子智能体 A = 实现 + 自测 + commit
       子智能体 B = 只读评审（独立上下文，不带实现者的自我辩护）

1 派实现  主会话给自包含 brief：工作区、commit base、要读的文档段落、交付物、硬约束、门禁命令
2 自测    实现者跑完门禁并把**实际输出**贴回；没跑过 = 未完成
3 派评审  独立评审方按 DoD + 本轮语义逐条判 PASS/CHANGES/BLOCKED
4 修复    CHANGES → 回给**同一个**实现者修（保留上下文），修复后重评；≤3 次，第 4 次转 BLOCKED 写裁决
5 验收    主会话核对：commit 只含本轮文件、门禁可复跑、diff 规模合理、无夹带
6 合并    PASS 后 merge 进 main（--no-ff，保留轮次边界）；分支继续用于下一轮
7 看板    更新 progress.html：状态、commit、评审原文发现、风险
          文档权威：01 决策 > 00 §2/§1.1 硬约束 > 02 顺序与验收 > 03 参考实现 > 00 其余。条款要改按 00 §0.3 分 L1/L2/L3。
          worktree 生命周期：整批 PR 完成（或方案中止）时由主会话删除；中途不删，避免反复重建 node_modules 软链与仓库索引。
